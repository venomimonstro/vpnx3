# Контур пользовательского доступа и VPN Worker

## Цель

VPN-узел не должен обращаться к центральной базе данных при каждой попытке подключения пользователя. Центральная система выдаёт короткоживущее подписанное право доступа, а worker проверяет его локально по заранее известному открытому ключу.

## Поток

```text
Устройство
  │ подписанный запрос устройства
  ▼
Control Plane
  │ проверка trial/подписки
  ▼
Access Lease
  │ Ed25519 подпись
  ▼
Устройство
  │
  ▼
VPN Worker / локальный модуль авторизации
  │
  ├─ проверка подписи
  ├─ проверка срока
  └─ разрешение / отказ
```

## Почему это важно

Полная потеря Control Plane не разрывает уже выданные краткоживущие права доступа. Компрометация VPN Worker не даёт закрытый ключ подписи и поэтому не позволяет самостоятельно создавать новые права доступа.

Модуль `vpn-worker` на текущем этапе реализует только независимый слой авторизации. Конкретный транспорт туннеля подключается следующим спринтом через отдельный адаптер. Это намеренное разделение: проверка коммерческого права доступа не должна зависеть от WireGuard, QUIC или другого транспорта.
