# VPNX3 — план разработки и фактический статус

## Правила разработки

- основная ветка: `main`;
- GitHub Actions/CI не используются;
- каждый спринт должен оставлять проект в логически согласованном состоянии;
- секреты не помещаются в Git;
- сетевой контур отделён от бизнес-логики;
- документ обновляется по факту реализации.

## Спринт 0 — фундамент Control Plane: ЗАВЕРШЁН

Реализованы PostgreSQL, версионные миграции, пул соединений, health/readiness, роли и разрешения, Argon2id для административных паролей, хешированные сессии, первичное создание владельца, append-only аудит, идентификаторы запросов, защитные HTTP-заголовки и контейнерное окружение.

## Спринт 1 — управление нодами: ЗАВЕРШЁН

Реализованы одноразовые коды подключения с хранением только хеша, Node Agent, индивидуальная Ed25519-идентичность нод, подписанные heartbeat-запросы, защита последовательностью от повторного воспроизведения, Linux-метрики, конечная машина состояний, publish/drain/maintenance/quarantine/retire, история состояний, автоматическое обнаружение heartbeat timeout и безопасный systemd-установщик с обязательной проверкой SHA-256.

## Спринт 2 — пользовательский доступ / Data Plane: В РАБОТЕ

Реализовано:

- анонимная регистрация устройства без обязательного email;
- Ed25519-идентичность устройства;
- пробный период как серверное право;
- защита подписанных запросов устройства от повторного воспроизведения;
- короткоживущий подписанный Access Lease;
- активная подписка и льготный период;
- отдельный ключ подписи права доступа;
- offline-проверка Access Lease на VPN Worker;
- единый интерфейс транспортного адаптера;
- локальный менеджер VPN-сессий;
- локальный пул IPv4-адресов;
- автоматическое освобождение истёкших сессий;
- первая реализация транспорта WireGuard через wgctrl;
- защита от двух сессий одного устройства с конфликтующим AllowedIP;
- локальный HTTP-контур управления worker;
- защищённый systemd-установщик worker с минимальной CAP_NET_ADMIN.

Осталось до закрытия спринта:

1. подготовка и проверка Linux WireGuard-интерфейса как отдельного инфраструктурного шага;
2. передача фактического числа сессий из worker в Node Agent;
3. сетевые счётчики Data Plane;
4. сквозной интеграционный тест «устройство → lease → worker → WireGuard peer → трафик»;
5. корректное восстановление после перезапуска worker.

## Спринт 3 — подписанная конфигурация: ОСНОВА ЗАВЕРШЕНА

Реализованы отдельный Ed25519-ключ конфигурации, версионные манифесты, публикация активных ingress, цифровая подпись, клиентская проверка, срок действия, защита от отката, Last Known Good cache, атомарная запись кеша и fallback.

Следующий уровень: физически независимые зеркала и аварийный корневой манифест.

## Спринт 4 — Android MVP: СЛЕДУЮЩИЙ

Kotlin + Jetpack Compose, локальная ключевая пара устройства, регистрация, получение подписанной конфигурации, Access Lease, VpnService, WireGuard-клиент, автоматическое переподключение и диагностика.
