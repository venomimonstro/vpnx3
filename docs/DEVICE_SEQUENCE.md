# Device request sequence durability

Подписанные запросы устройства используют монотонный `request_sequence` для защиты от replay.

Клиент обязан резервировать и синхронно сохранять следующий sequence **до сетевого запроса**.

Почему:

1. клиент отправил sequence=42;
2. сервер проверил подпись, применил запрос и сохранил 42;
3. HTTP-ответ потерялся;
4. если клиент сохранял sequence только после ответа, он снова отправил бы 42;
5. сервер правильно отверг бы его как replay, и клиент мог бы застрять.

VPNX3 Android теперь использует `SharedPreferences.commit()` при резервировании sequence. Неиспользованные номера допустимы; повторное использование — нет.
