# Криптографические конверты

## Проблема

Нельзя подписывать байты JSON, затем сохранять объект в JSONB или позволять промежуточному клиенту пересериализовать вложенный объект и ожидать, что цифровая подпись останется валидной. Пробелы и порядок представления могут измениться при сохранении/передаче.

## Решение VPNX3

Все подписываемые документы передаются как непрозрачные байты:

```json
{
  "payload": "BASE64URL_EXACT_SIGNED_BYTES",
  "signature": "BASE64URL_ED25519_SIGNATURE",
  "key_id": "..."
}
```

Это применяется к:

- Configuration Manifest;
- Access Lease;
- будущим аварийным манифестам.

Проверяющая сторона:

1. декодирует `payload`;
2. декодирует `signature`;
3. проверяет подпись непосредственно над декодированными байтами;
4. только после успешной подписи разбирает JSON payload;
5. проверяет схему, срок и номер версии.

PostgreSQL может дополнительно хранить JSONB-копию для аналитики, но криптографическим источником является только `payload_raw BYTEA`.
