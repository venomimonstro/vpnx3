# VPNX3

VPNX3 — распределённая VPN-платформа с централизованным управлением, индивидуальной идентичностью нод и устройств, подписанной клиентской конфигурацией, короткоживущими правами доступа и автоматическим контролем состояния сети.

Основной концепт: `docs/CONCEPT.md`.

Фактический статус: `docs/ROADMAP.md`.

## Производственная установка

Производственная установка основного сервера: [docs/PRODUCTION_INSTALL.md](docs/PRODUCTION_INSTALL.md).
Используйте `docker-compose.production.yml` и двухэтапный `scripts/install-control-production.sh prepare|deploy`.

**Важно:** обычный `docker-compose.yml` содержит настройки для разработки и не должен применяться на боевом сервере.

## Локальный запуск Control Plane

1. Создать окружение:

```bash
cp .env.example .env
```

2. Сгенерировать независимые ключи подписи:

```bash
go run ./cmd/keygen
```

Перенести `VPNX3_CONFIG_SIGNING_KEY` и `VPNX3_ACCESS_SIGNING_KEY` в `.env`.

3. Задать первоначальные данные владельца. Пароль нужен только при инициализации пустой базы.

4. Запустить:

```bash
docker compose up --build
```

Сервис миграций завершается до запуска Control Plane.

## Основные процессы

- `cmd/controlplane` — центральное управление;
- `cmd/migrate` — миграции PostgreSQL;
- `cmd/node-agent` — агент ноды;
- `cmd/vpn-worker` — локальная offline-проверка Access Lease;
- `cmd/keygen` — генерация независимых ключей подписи.

## Безопасность

Не коммитить `.env`, закрытые ключи или реальные enrollment-токены. Каждая нода и каждое устройство имеют собственную Ed25519-пару. VPN Worker получает только открытый ключ проверки Access Lease и не способен выпускать новые права доступа.
